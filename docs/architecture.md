# Architecture: Gitleaf

> This is the source of truth for agents and contributors. When something here changes, add an ADR in `docs/adr/`.

## Goal and non-goals

**Goal:** remove external documentation tools. All documentation lives as Markdown in git, in one or many repositories. It is reviewable like code, attributable line by line to a person or an agent, and fully manageable by AI agents (Copilot, Claude) under human review.

**Non-goals:**

- A git client. VS Code's built-in Source Control, graph, blame, timeline and merge editor already exist, and Gitleaf builds on them.
- A hosted wiki server. Gitleaf may publish a read-only static site for readers who never open VS Code, generated by CI.
- A secrets manager. Gitleaf stores references only.
- Real-time co-editing. Git is asynchronous, and Gitleaf designs for that.

## Modules (priority order)

| # | Module | What it does | Builds on |
|---|---|---|---|
| 1 | **Docs core** | Multi-repo doc index, frontmatter (owners, status, tags, id), links and backlinks, search, templates, docs-health checks (broken links, stale or ownerless docs) | Built-in Markdown preview, link validation and Mermaid |
| 2 | **Review and git** | Docs-aware changes view, rendered Markdown diffs, a commit composer with agent assist, branch/PR creation, review and merge | `vscode.git` API (status, commit, branches, fetch/pull/push, `merge`, `rebase`, `log`, `blame`, diffs); GitHub Pull Requests extension for GitHub; Gitleaf's own small review panel for **Azure DevOps** (no official VS Code UI exists), using the ADO REST API or ADO MCP server |
| 3 | **Provenance** | Who wrote each line: human, agent or mixed, in which commit and PR, approved by whom | `git blame` + commit trailers (`Co-authored-by`, Claude Code `attribution`, VS Code `git.addAICoAuthor`) + **Agent Trace** records in git notes (`refs/notes/ai`) where available |
| 4 | **Agent layer** | One MCP server (search, read, create, edit, validate, propose changes, review summaries) plus shipped skills | VS Code `mcpServerDefinitionProviders`, `chatSkills` and `languageModelTools`; a Claude Code plugin (skills + `.mcp.json`) from a marketplace repo. VS Code Agent Plugins read the same format. |
| 5 | **Import** | Confluence, Notion, Google Docs and SharePoint to Markdown, with link, image and frontmatter cleanup | Wraps existing converters (confluence-markdown-exporter, Notion export, Google Docs Markdown export, MarkItDown, pandoc) |
| 6 | **Appearance** | Neutral default, optional Gitleaf themes, and installable **appearance packs** | Contributed colors, a declarative `gitleaf.appearances` contribution, `configurationDefaults` |
| 7 | **Agile module** (optional) | Backlog, sprints, board, async planning poker, retros as files | Same core. Format in `.claude/rules/file-formats.md` |

## Shape (hexagonal)

```
VS Code UI ─┐   ┌──────────────── core (pure TS) ────────────────┐
CLI        ─┼──▶│ Doc · Repo · Change · Review · LineOwner ·      │◀── ports ──▶ fs · git · forge · secrets · notes
MCP server ─┘   │ Appearance · (agile entities)                   │
                └─────────────────────────────────────────────────┘
```

**Ports:**

- `WorkspaceStore`
- `VcsPort`, implemented by the `vscode.git` API in the extension and by the git CLI in the CLI and CI
- `ForgePort` (PRs, reviews, merge): GitHub and Azure DevOps first, GitLab later
- `ProvenancePort`: blame + trailers + git notes
- `SecretsPort`: metadata only
- `IdentityPort`
- `Clock` and `IdGenerator`

## Key flows

- **Edit a doc.** The user or an agent edits Markdown. On save, Gitleaf validates frontmatter and links and shows problems in the Problems panel. The changes view groups the edits by doc, and the commit composer drafts a message (with agent help) that keeps the attribution trailers.
- **Review.** A PR is opened, through the GitHub PR extension or Gitleaf's ADO panel. Reviewers see a rendered Markdown diff (`workbench.diffEditorAssociations` for `*.md`) and a provenance overlay showing which lines are agent-written and which humans approved. They approve and merge from the UI. Agents can summarize, propose fixes and answer review threads, but **never approve or merge**.
- **Trace a line.** Hovering a line shows the person or agent, commit, PR and approver. A per-doc provenance view shows the human/agent share over time.
- **Agent task.** For example: "Move the onboarding pages from Confluence into `docs/onboarding`". The skill runs the import tool, writes files on a branch, validates them and opens a PR. A human reviews and merges.

## Repository convention (for user repos)

```
gitleaf.yaml                 # roots, doc rules, forge settings, appearance hints (no secrets)
docs/**.md                   # any structure; frontmatter optional
.claude/settings.json        # extraKnownMarketplaces + enabledPlugins → Gitleaf plugin for Claude and VS Code agents
AGENTS.md                    # generated stub pointing agents at Gitleaf tools
agile/**                     # only if the agile module is enabled
```

## Security model

- All repo text is untrusted input to agents. Tool results wrap file content as data.
- Write, commit, push and merge actions require confirmation, and agents can't approve or merge.
- Workspace Trust uses `limited` support. In Restricted Mode Gitleaf is read-only.
- Appearance packs are declarative: CSS custom properties only, sanitized SVG, and JSON copy rendered as text.
- Webview CSP is `default-src 'none'`.
- Secrets are references only, with gitleaks enforced locally and in CI.

## Roadmap

| Phase | Scope |
|---|---|
| 0: Foundations | Scaffold + CI + identity guard; doc and config schemas; canonical format; `gitleaf validate`; provenance spike; MCP server v0 (read, search, validate) for both agents; appearance loader + neutral tokens; themes package |
| 1: MVP | Docs explorer across repos; changes view and commit composer; rendered diff review; provenance hover and view; GitHub PR handoff; ADO review panel (comment, vote, merge); agent edit, propose and review-summary tools; import from Confluence and Notion |
| 2: v1 | Static docs site from CI, docs-health dashboard, Google Docs and SharePoint import, appearance pack scaffold command, agile module (board, poker, retro) |
| 3: Later | GitLab, cross-repo doc graph, more appearance packs |

**MVP exit test:** a team retires one Confluence space. Its pages live in git, every change goes through review in VS Code, and for any line you can answer who (or which agent) wrote it and who approved it.
